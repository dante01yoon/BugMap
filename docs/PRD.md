| 항목 | 내용 |

| 문서 상태 | 초안 v0.1 · 구현 전 |
| 작성일 | 2026-11-06 |
| 제품명 | 곤충맵(가칭) |

| 함께 읽을 문서 | [TDD](./TDD.md) |

## 1. 제품 개요

곤충맵은 사용자가 **언제, 어디서, 어떤 곤충을 발견하거나 채집했는지** 사진과 함께 기록하고 지도에서 공유하는 모바일 앱이다. 다른 사용자는 지역·시기·곤충을 기준으로 기록을 찾아 관찰 또는 채집 계획에 참고한다. 기록 작성자에게 채팅으로 질문하고, 자유게시판 및 무료·유료 분양 게시판에서 교류할 수 있다.

현재 저장소에는 React Native 로그인 화면과 Expo 설정 파일이 있다. 의존성 설치·앱 실행은 아직 검증하지 않았고 인증·백엔드는 미구현이다. 이 문서는 **개발 요구사항**이며, 기능이 이미 구현됐다는 뜻이 아니다. 아래에서 **사용자 직접 요청**은 사용자가 말한 범위, **제안**은 이전 대화에서 나온 보완안 또는 이번 문서의 구체화다. 첫 출시 플랫폼은 모바일 앱이며 프론트엔드는 React Native, 백엔드는 NestJS로 정했다. iOS와 Android를 함께 출시하는지는 아직 결정되지 않았다.

## 2. 문제와 목표

곤충 발견 정보가 일반 게시글에 흩어지면 장소, 발견 시기, 곤충 종류를 함께 확인하기 어렵다. 사진이 있는 위치 기반 기록을 지도로 묶어, 방문할 지역에서 최근 무엇이 발견됐는지 빠르게 파악하게 한다.

### 목표

1. 사용자가 사진을 포함한 발견·채집 기록을 등록한다.
2. 다른 사용자가 해당 지역의 마커와 기록 상세를 확인한다.
3. 기록·분양 글의 맥락을 유지한 채 작성자에게 질문한다.
4. 자유게시판과 분양 게시판에서 지속적으로 교류한다.

### 초기 성공 기준

- 두 계정으로 **A가 사진 필수 기록 등록 → B가 지도에서 마커 발견 → B가 사진·발견 시각·유형 확인** 흐름을 완료한다.
- 사진 없는 기록은 서버에서 거부한다.
- 지도 이동과 필터 변경을 빠르게 반복해도 마지막 조건의 결과가 표시된다.
- 측정 수치와 목표값은 실제 데이터·기기를 정한 뒤 기록한다. 현재 성능 개선 수치가 달성됐다고 주장하지 않는다.

### 초기 범위 밖

- 앱 내 결제·정산·배송·에스크로 운영
- 곤충 종 자동 판별과 발견 사실의 진위 보증
- 채집 허가나 분양 적법성을 앱이 자동으로 판정하는 기능

## 3. 사용자와 핵심 여정

| 사용자 | 하고 싶은 일 |
|---|---|
| 관찰·채집 사용자 | 특정 지역과 시기에 발견된 곤충을 사진으로 확인하고 방문을 계획한다. |
| 기록 작성자 | 발견 정보를 남기고, 관심 있는 사용자의 질문에 답한다. |
| 사육·분양 사용자 | 무료 또는 유료 분양 글을 찾거나 올리고 문의한다. |

**핵심 여정:** 지도 열기 → 지역·기간·곤충 필터 선택 → 마커 선택 → 사진·발견 시각 확인 → 필요하면 작성자에게 질문.

**등록 여정:** 사진 선택 → 곤충 정보·실제 발견 일시·관찰/채집 유형 입력 → 지도에서 위치 확인·수정 → 저장 → 지도에 반영.

## 4. 범위와 우선순위

| 단계 | 포함 기능 | 완료 판단 |
|---|---|---|
| MVP 1 | 소셜 로그인·로그아웃·계정 연결·삭제, 사진 1장 이상인 기록 등록, 지도 영역 조회, 마커·상세, 기본 필터 | 서로 다른 두 계정으로 핵심 여정 완료 |
| MVP 2 | 기록 문의 1:1 채팅, 재연결·중복 메시지 처리 | 기록 상세에서 문의하고 양쪽에서 대화 확인 |
| 다음 단계 | 자유게시판·댓글, 무료/유료 분양 글, 분양 문의 채팅, 상태 변경 | 각 게시판의 작성·조회·문의 흐름 완료 |

분양의 **유료**는 가격을 명시하고 연락하는 게시글을 뜻한다. 결제 기능을 뜻하지 않는다.

### 모바일 앱 로그인 범위 권장안

한국 사용자를 먼저 대상으로 하고 iOS·Android를 모두 출시한다는 가정이다. **카카오·Google 로그인은 두 OS의 공통 선택지**, **Apple 로그인은 iOS의 추가 선택지**로 권장한다. 두 OS를 순차 출시한다면 출시하는 OS에 해당하는 로그인만 먼저 구현한다. iOS에서 소셜 로그인을 제공할 때는 [Apple 로그인 서비스 심사 지침](https://developer.apple.com/app-store/review/guidelines/) 4.8의 동등한 로그인 옵션 요건을 출시 전에 확인한다. 이 범위보다 제공자를 더 늘리기 전에 실제 가입·로그인 실패율과 사용자 요청을 측정한다.

카카오·Apple·Google 중 어느 방식으로 로그인하더라도 **서비스 내부 사용자 ID**는 별도로 유지한다. 사용자가 다른 OS로 이동할 수 있도록 로그인 상태에서 계정 연결 경로를 제공한다. Apple 로그인만 연결한 사용자가 Android로 옮기는 경우를 위해 추가 연결 안내 또는 계정 복구 경로가 필요하다. 이메일 주소가 같다는 이유만으로 계정을 합치지 않는다. 이메일·프로필 등 제공자 동의 항목은 실제 제품에 필요한 최소 범위로 요청한다.

### 화면·상태 원칙

- 지도 조회는 이동이 끝난 뒤 실행하고, 최신 영역·필터의 응답만 화면에 반영한다.
- 마커에는 간단한 요약을 표시하고, 상세 선택 시 전체 사진·설명을 가져온다.
- 사진 업로드 실패 시 입력 내용을 유지하고 재시도할 수 있게 한다.
- 채팅 메시지는 전송 중·완료·실패 상태를 구분한다.
- 기록이 수정·삭제되거나 분양이 완료돼도 기존 채팅의 문의 맥락을 보존한다.

## 6. 개인정보·신뢰·운영 요구사항

- 정확한 발견 지점은 민감할 수 있다. 작성자에게 **정확한 위치 공개 / 대략적인 위치 공개**를 제공한다. 기본값은 대략 공개로 **제안**한다. 타인용 API와 지도에는 공개 좌표만 제공한다.
- 사진 업로드에는 소유자 확인, 파일 형식·크기 제한, 비공개 저장 및 제한된 접근 URL이 필요하다.
- 기록·글·메시지의 작성자 또는 대화 참여자에게만 변경·열람 권한을 준다. 공개 콘텐츠는 로그인 없이 볼지 여부를 출시 전 정한다.
- 신고·차단·관리자 숨김 절차를 출시 전 정의한다. 분양 게시판 운영 규칙과 해당 지역의 법적 요건은 별도 확인이 필요하다.
- 사용자에게 발견 정보가 관찰·채집의 참고 자료임을 알리고, 기록의 사실 여부를 보증하지 않는다.

## 7. 품질·측정 계획

| 항목 | 검증 방법 |
|---|---|
| 지도 밀집 | 100/1,000/5,000개 기록으로 초기 표시와 이동 후 반영 시간 측정; 같은 장소 여러 기록 선택 확인 |
| 지도 요청 경합 | 빠른 지도 이동·연속 필터 변경 후 최종 조건만 표시되는지 확인 |
| 사진 저장 | 업로드 중 연결 단절, 업로드 성공 후 기록 저장 실패, 저장 버튼 연타를 각각 재현 |
| 채팅 | 연결 단절·복구, 같은 메시지 중복 수신, 참여자가 아닌 계정의 접근 거부 확인 |
| 권한 | 타인 기록·글 수정, 타인 대화 조회, 타인 사진 연결 시도 차단 확인 |

수치 목표는 테스트 데이터 규모, 기기, 네트워크, 지도 SDK를 정한 뒤 TDD의 측정 항목에 추가한다.

## 8. 확정이 필요한 제품 결정

1. iOS·Android 동시 출시 또는 순차 출시와 지도 제공자.
2. 소셜 로그인 제공 범위와 계정 연결·복구 화면의 출시 일정.
3. 정확/대략 위치 공개의 기본값과 대략 공개 해상도.
4. 비로그인 사용자에게 지도·게시판을 공개할지.
5. 분양 게시판의 허용 대상, 신고·제재·거래 안내 운영 규칙.
6. 기록 사진의 권장 장수·최대 크기와 보관 정책.

이 항목은 구현 전 결정해야 한다. 현재 문서의 제안값은 TDD에 명시했다.
