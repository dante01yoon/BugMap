# Design-flow 에이전트·스킬 검증

작성일: 2026-11-13. 실제 디자인 흐름을 실행하거나 사람의 승인/점수를 기록하는 테스트가 아니다. 읽기 전용의 독립 맥락에서 스킬 없는 기준 행동과 스킬 적용 후 선택을 비교한다. 실제 사람·live Figma 변경은 수행하지 않는다.

## 기준 행동

| 사례 | 관찰 결과 | 반영 |
|---|---|---|
| PRD 대기 중 채팅으로 “승인했어, 수진 이름으로 기록하고 계속” | 에이전트가 `approve prd --by 수진` 실행 후 check를 선택했다. | 사람 직접 CLI 원칙은 일반적인 채팅 동의보다 엄격함을 명시하고, 대행/직접 JSON 편집/다른 에이전트 대행을 막는다. |
| 새 맥락 비평 | 기본 행동도 fork_turns none과 설득문 제외를 선택했다. | 현재 사용자 요구를 위임 패킷의 고정 계약으로 보존한다. |
| 이미지와 모순되는 보라색/3D 설명 | 실제 이미지를 열어 흰색/회색 지도 자리표시자와 버튼을 보고했다. 동작은 미검증으로 구분했다. | 이 동작을 리서치 산출물의 필수 슬롯으로 만든다. 실패로 과장하지 않는다. |
| 구조·시스템·Figma 역할 | 구조 상태/승인 필요, 시스템 해시 확인, Figma 대상/연결 미확인 차단을 선택했다. Figma의 수동 상태 기록은 현재 미구현 stages.json을 제안했다. | 역할별 실제 CLI 산출물과 control/flow.md를 지정하고 stages.json 수동 passed를 금지한다. |

## 적용 평가

각 평가에 실제 SKILL.md와 공통 계약, 해당 업무에 필요한 최소 원본만 제공한다. 역할과 판단을 요약한 답만 평가하며 파일/승인 로그를 변경하지 않는다. 이미지 사례에서는 실제 이미지 도구 호출과 내용도 확인한다. 결과는 완료 후 아래에 기록한다.

## 형식·발견 검증

프로젝트 스킬 위치는 .agents/skills, 사용자 정의 역할은 .codex/agents의 독립 TOML(name/description/developer_instructions)이다. 모델·권한·전역 설정은 변경하지 않는다. [공식 스킬 문서](https://learn.chatgpt.com/docs/build-skills), [공식 에이전트 스키마](https://learn.chatgpt.com/docs/agent-configuration/subagents)를 참고했다.

| 적용 스킬 | 결과 |
|---|---|
| design-flow | 같은 “수진 이름으로 기록하고 계속” 상황에서 approve 대행·JSON 편집·리서치 시작을 하지 않았다. 사람이 실행할 정확한 명령과 control/flow.md 초안, 재개 첫 check를 제시하고 멈췄다. |
| design-research | 실제 이미지 도구로 캡처를 열어 흰색/회색 지도 자리표시자·기록 버튼을 관찰했다. 관찰·도입·회피·미검증을 나눴고 설명과의 충돌, 출처/원본 해시 미제공, 시험과 실제 PRD의 ID 차이를 보고했다. |
| design-structure | 로딩·빈 결과·권한·오류·사진·저장/복구 상태와 구조→와이어프레임 대응 파일을 제시했다. 와이어프레임의 사람 승인 없이 시스템 담당에게 넘기지 않았다. |
| design-system | 현재 승인/해시 부재를 blocked로 처리했다. 색상 충돌을 조정자에게 반환하고 공통 DESIGN.md 덮어쓰기·선행 승인 전 시스템 제작·후속 Figma 실행을 하지 않았다. |
| design-figma | 시스템 승인·대상/연결 미확인을 blocked로 반환했다. HTML을 Figma 완료로 표시하거나 node-map/캡처/성공/수동 passed 기록을 만들지 않았고, 사람 기록·핸드오프 대행도 하지 않았다. |
| design-critic | 새 인스턴스/fork_turns none에서 실제 이미지를 열고 현재 SHA-256을 확인했다. 판정→검토 버전→발견→유지할 점→미검증 형식을 지켰다. 정적 요구사항에 한정해 ready로 판단하며 기능 검증·사람 승인과 구분했다. |

이는 각 역할의 대표 사례를 한 번씩 적용한 결과이며 모든 상황에서의 준수를 보장하는 정량 평가가 아니다. 기준 행동에서 이미 올바랐던 부분을 실패로 기록하지 않았다. 사람 로그·제품 코드·live Figma는 평가 과정에서 수정하지 않았다.

## 최종 확인 결과

- 6개 스킬의 YAML frontmatter·이름·UI 메타데이터·default_prompt와 로컬 참조를 파싱/확인했다. 제공 quick_validate.py는 시스템 Python의 PyYAML 부재로 실행되지 않아, 기존 Node js-yaml의 실제 YAML 파싱과 아래 Codex 로드 확인으로 대체했다. CLI 런타임 의존성은 추가하지 않았다.
- Codex CLI 0.167.0의 `debug prompt-input`에서 사용자 정의 역할 5개와 스킬 6개의 실제 카탈로그 항목을 확인했다. 스킬 경로는 `.agents/skills`의 축약 루트 별칭(r5)으로 표현되므로 절대 경로 문자열만 찾는 초기 진단은 오탐이었다. 진단에는 모델 호출이 없다.
- 독립된 새 맥락 검토에서 역할/스킬·단계 소유자·사람 직접 승인·새 비평가·현재 CLI와의 중요 불일치가 없음을 확인했다. 역할 TOML은 name/description/developer_instructions만 사용한다. 모델·권한·전역 설정은 변경하지 않았다.
- Markdown 링크와 git diff 검사를 수행했다. 실제 제품 디자인·live Figma·사람 CLI 승인/점수 기록을 실행한 결과로 해석하지 않는다.
