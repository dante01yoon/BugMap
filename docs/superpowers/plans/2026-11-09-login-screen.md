# 로그인 화면 구현 계획

**목표:** 현재 선택된 Figma `2:3`을 React Native 로그인 화면으로 옮긴다. 인증과 서버 기능은 포함하지 않는다.

**구조:** 루트 Expo·TypeScript 앱과 `src/features/auth` 화면을 만든다. 디자인 토큰, 원본 아이콘 자산과 화면 데이터를 분리한다. NestJS는 실제 API 작업 때 시작한다.

**기준:** PRD·TDD의 React Native 선택, DESIGN.md, 선택 프레임 `2:3`과 배경 프레임 `2:2`. 기능 소개·소셜 제공자는 선택 시안을 따른다. AI·통계·보안 문구는 실제 제공 기능/수치로 확정하지 않는다.

- [x] Expo 진입점, 앱 설정, TypeScript·실행 스크립트·무시 파일 작성.
- [x] Figma 아이콘을 로컬 자산으로 저장하고 출처·치수를 기록.
- [x] 브랜드 헤더·가로 소개 카드·페이지 표시·소셜 버튼·보조 동작·안내 영역 구현.
- [x] 좁은 화면 스크롤, 안전 영역, 접근성 라벨과 미연동 동작 코드 작성. 실행 검증은 미완료.
- [ ] 패키지 설치·타입 검사·웹 번들 검증, 가능하면 브라우저 캡처 대조.
- [x] 설치/런타임 차단 시 검증 범위를 README·TDD·DESIGN에 기록. 실행 완료로 표시하지 않는다.

검증 기록: npm registry `ENOTFOUND`, 오프라인 `ENOTCACHED`; 자산 16개 검사 통과, TS/TSX 6개 구문 변환 진단 0개. 전체 타입 검사는 미설치 모듈/Expo 설정으로 실패하고 웹 시작은 `expo: command not found`로 실패했다. 이 검증 항목은 미완료로 유지한다.

현재 환경은 Git 저장소가 아니므로 기존 폴더에서 작업한다. npm 접속이 `ENOTFOUND`로 실패했다. 설치가 불가능해도 가짜 의존성/타입으로 검증 성공을 만들지 않는다. 이번 변경은 정적 화면이므로 구현을 그대로 복제하는 단위 테스트 대신 타입·번들·시각 검증을 우선한다.
