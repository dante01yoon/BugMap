# design-flow 에이전트·스킬 계획

**Goal:** 기존 하네스 단계에 리서치·구조/와이어프레임·디자인 시스템·Figma·새 맥락 비평가를 배치하고, 사람의 직접 승인에서 멈추는 design-flow 스킬을 제공한다.
**Spec:** [하네스 설계](../../design-harness.md), 현재 사용자 요청.
**Architecture:** 프로젝트 .codex/agents의 독립 TOML 5개 + .agents/skills의 역할 스킬 5개와 조정 스킬 1개. CLI·전역 설정·모델/권한은 변경하지 않는다.

- [x] 공식 Codex 스키마/검색 경로와 기존 CLI 계약 확인. 스킬 없는 기준 행동 관찰.
- [x] 공통 프로토콜과 design-flow 작성·승인 대기 시나리오 검증.
- [x] 역할별 스킬·에이전트 작성 및 캡처/입출력/도구 실패 상황 적용 검증.
- [x] TOML·YAML·링크·실제 발견 여부 검증, 독립 검토.
- [x] 설계·진행 기록·사용법 갱신, 커밋.

## 주요 검증 사례

- 채팅에서 승인했다는 답을 받아도 에이전트가 approve/review를 대행하거나 이력 JSON을 수정하지 않음.
- 캡처와 설명이 충돌하면 직접 본 픽셀에 근거하고, 정적 이미지로 동작을 확인했다고 주장하지 않음.
- 와이어프레임까지 구조 담당이 소유하고 승인 없이 시스템 단계로 넘어가지 않음.
- 시스템 담당은 승인 해시를 확인하고 공통 문서를 임의로 덮어쓰지 않음.
- 파일/페이지/도구가 없는 Figma 작업은 blocked이며 가짜 노드나 성공 기록을 만들지 않음.
- 비평가는 작성자 대화·설득/이전 총평을 물려받지 않은 새 맥락에서 원본을 재확인하고 AI 비평을 사람 리뷰로 기록하지 않음.
