# 결정과 미결정

## 사용자 확정

- 현재 연결된 Figma 페이지에 첫 화면(로그인)을 디자인한다. 기존 시안이 있으며 이번 목적에는 디자인 하네스가 적용되는지 확인하는 것이 포함된다.
- 일반 UI 아이콘은 Lucide를 사용하며 Figma 아이콘을 복사/추출하지 않는다.
- 사람의 approve/review는 사람이 직접 수행한다. 대화의 과거 디자인 생성/현재 디자인 요청은 하네스의 해시 기반 단계 승인을 대신하지 않는다.

## 이번 PRD에 포함한 제안 — 승인 전

- 앱 전체와 분리한 bugmap-login 실행으로 로그인 진입 화면과 관련 상태만 다룬다. 기본 캔버스는 390×844, 좁은 화면 검증은 360×800이다.
- Page 1에 새 비교 프레임을 추가하고 기존 노드 1:2, 2:2 및 다른 화면은 수정하지 않는다.
- 기존 시안 및 직전 로고 대화의 카카오·네이버·Apple을 이번 UI 검토 대상으로 유지한다. 이는 백엔드 제공자 채택이 아니다. docs/PRD.md의 Google 권장안과 충돌하므로 첫 승인에서 UI 범위를 확인한다.
- 일반 UI와 소셜 제공자 브랜드 표식을 구분하고 제공자 로고는 공식 자산/공식 버튼으로만 사용한다. docs/DESIGN.md와 docs/screens/login.md의 일반 Lucide 기호 대체 규칙을 변경할 필요가 있다. 해당 예외는 PRD 승인 후 기준 문서에도 반영하며 Figma에서 로고를 추출하지 않는다.
- 이메일 로그인과 비회원은 제품 정책/도착 화면이 미정이므로 이번 시안에서 로그인 가능한 주 동작처럼 제공하지 않는다. 필요하면 비활성·예정 상태로 명시한다.

## 미결정과 다음 단계

- 출시 OS 순서, 실제 인증 SDK·API, 비회원 공개 정책, 약관 URL/운영 문구는 이번 디자인 실행에서 확정하지 않는다.
- 로컬 Figma 브리지 재연결로 키가 바뀌면 같은 파일인지 다시 확인하고 설정 변경에 따른 기존 승인 무효화를 처리한다.
- 실제 훅이 runtime에 설치·신뢰됐는지와 훅 함수의 로컬 진단 결과를 구분한다. 로컬 진단을 실제 MCP 차단 실행으로 보고하지 않는다.
- 기존 sourceDocuments 해시는 착수 버전 기록이다. 원본 변경 자동 추적이 아니므로 매 재개 시 대조한다.
