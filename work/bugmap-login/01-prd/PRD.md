# 곤충맵 로그인 첫 화면 PRD

상태: 승인 전. 날짜: 2026-11-13. 실행: bugmap-login.

## 목적·사용자·성공 기준

처음 곤충맵을 방문한 관찰·채집 사용자가 앱의 지도 기반 곤충 기록/공유 목적을 이해하고, 본인이 사용할 소셜 로그인 경로를 알아볼 수 있도록 첫 화면을 디자인한다. 기존 시안을 참고하되 실제 하네스의 근거·단계·사람 승인 기록으로 새 시안을 만든다.

성공은 편집 가능한 Figma 화면/상태, 동일 버전의 실제 캡처·노드 매핑·내보내기, lint:figma 및 대응 HTML lint:web, 사람의 최종 검토/승인이 있는 디자인 전달이다. 원격 인증/세션/SDK 동작 성공을 의미하지 않는다.

## 근거와 현재 화면

- 상위 요구사항: docs/PRD.md의 AUTH-01 및 로그인 상태 원칙. AUTH-02~05의 로그아웃·계정 연결/삭제는 이번 화면 밖이다.
- 시각/기술 기준: docs/DESIGN.md, docs/screens/login.md, docs/TDD.md. 원본 버전은 control/project.json에 해시로 기록한다.
- 참조 대화 01a1bfa0-405f-7523-9db5-7644b9d34023을 read_thread로 읽었다. 과거 생성 작업은 현재 단계 승인이 아니다.
- 현재 원격 MCP 조회: BugMap, Page 1(0:1). 기존 로그인 1:2(390×844), 가져온 로그인 2:2(390×884)를 2026-11-13 PNG로 다시 캡처해 baseline/에 저장하고 직접 확인했다.
- 1:2는 현재 캡처에서 제목/일러스트와 Google 행이 보이지만 다른 로그인 동작은 비어 있거나 제대로 읽히지 않는다. 과거 연결 중단 기록과 일치하는 부분이며 전체 정상 동작을 주장하지 않는다.
- 2:2에는 카카오·네이버·Apple 세 버튼과 가로 카드가 보인다. 일부 카드가 화면 밖에 있고 실시간·제보 수·암호화 등 미확정/미검증 문구가 있다. 현재 정상 로고처럼 보이는 원격 시안과 앱의 Lucide 대체 기호 문제를 구분한다.

## 범위와 핵심 여정

포함: 로그인 진입 화면, 짧고 사실에 맞는 가치 설명, 소셜 경로 식별, 공식 브랜드 표식, 약관/개인정보 동작의 위치와 미정 표시, 로그인 요청 중·취소 복귀·네트워크 실패 후 재시도·제공 불가 상태의 디자인. 기본 390×844 및 360×800에서 콘텐츠 접근과 44px 이상 조작 영역을 확인한다.

여정: 첫 화면 → 제공자 선택 → 요청 중 → 성공 시 지도 화면으로 이동한다는 명세 또는 취소/실패 시 로그인으로 복귀 → 재시도. 성공 도착 화면의 신규 디자인은 제외한다. Figma 프로토타입 연결 여부는 구조 단계에서 정하고 실제 연결한 것만 조작 검증한다.

제안 제공자는 기존 화면/직전 사용자 로고 대화 기준 카카오·네이버·Apple이다. 상위 PRD의 카카오·Google·Apple 권장안과 차이는 control/decisions.md에 기록했다. 이번 UI 범위 승인으로 제공자 구성을 확인하며 실제 인증 도입은 별도 결정이다.

이메일/비회원 경로는 대상/정책이 정해지기 전까지 사용 가능한 주 동작처럼 표시하지 않는다. 새 시안은 기존 로그인·지도·기록 작성 노드와 분리된 새 프레임으로 만든다.

## 수용 조건

requirements.csv의 LOGIN-01~09를 화면/상태와 연결한다. 핵심 조건은 다음과 같다.

- 서비스 목적을 지도·사진 기반 곤충 기록/공유로 설명한다. AI 자동 식별, 정확도/사용자 수/가입 시간 보장, 암호화·실시간 성능을 근거 없이 약속하지 않는다.
- 소셜 경로는 텍스트와 공식 브랜드 표식으로 구분한다. 일반 UI는 Lucide, 제공자 로고는 공식 자산/버튼을 사용한다는 예외를 승인 후 기준 문서에 반영한다.
- 로딩·실패·취소·제공 불가의 메시지와 복구 동작이 있으며 중복 요청을 방지하는 상태를 표현한다.
- 좁은 viewport에서 버튼·문구·약관에 접근할 수 있고 필수 텍스트가 잘리지 않는다. 주요 버튼 높이는 48px, 모든 조작 영역은 최소 44×44px이다.
- 기존 원격 노드를 유지하며 새 결과의 실제 파일/페이지/노드 ID·캡처·내보내기·검사 근거를 보존한다.
- PRD→리서치→구조→와이어프레임→시스템→Figma→검증→핸드오프를 따른다. 승인 필수 1·4·5·7·8에서 사람의 직접 기록이 없으면 멈춘다.

## 범위 밖·미검증

실제 인증 SDK/API·계정/세션·로그아웃/계정 삭제·정책 문서 작성·실제 메인 지도 구현·배포·앱 코드 수정·외부 게시를 포함하지 않는다. 시각 시안이나 HTML 검사를 실제 인증 동작 검증으로 표시하지 않는다. 공식 브랜드 자산의 최신 사용 지침 확인과 레퍼런스 분석은 PRD 승인 뒤 리서치 단계에서 수행한다.

## 승인할 내용과 재개

로그인만을 위한 범위, 위 제공자/브랜드 예외, 검증할 상태/크기, 기존 노드 보존, 실제 인증 제외를 검토한다. 사람이 저장소 루트에서 `node tools/design-harness/bin/design-harness approve prd --project bugmap-login --by '본인 이름'`를 실행한다. 조정자는 승인 명령이나 사람 로그를 대행하지 않는다. 실행 후 check로 유효성을 확인한 뒤 다음 단계로 간다.
