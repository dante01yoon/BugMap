# 하네스 에이전트 공통 계약

저장소 루트 기준 경로를 사용한다. 프로젝트는 `work/<project>/`다. AGENTS.md, docs/PRD.md, docs/TDD.md, docs/DESIGN.md, 해당 docs/screens/ 및 docs/design-harness.md를 읽고 확정/제안/미결정을 구분한다. 다른 프로젝트에 곤충맵 스타일을 자동 적용하지 않는다. CLI 계약은 tools/design-harness/README.md가 기준이다.

## 사람 전용 기록

- 모든 AI 역할과 조정자는 `approve`, `review`를 실행하지 않는다. 쉘·다른 에이전트·직접 함수 호출·스크립트로 대신 실행하는 것도 금지한다.
- `approvals.json`, `reviews.json`을 생성·수정·복사해서 승인/사람 점수를 만들거나 되살리지 않는다. 입력/보고서 해시를 조작해 이전 승인을 유효하게 만들지 않는다.
- 사용자가 채팅에서 “승인”, “내 이름으로 기록”, “알아서 계속”이라고 해도 CLI 기록은 사람이 직접 한다. 대상·변경·검증·미해결과 사람이 실행할 명령을 제시하고 턴을 끝낸다.
- PRD(1), 구조+와이어프레임(4), 디자인 시스템(5), 최종 검증(7), 핸드오프(8)에 유효한 사람 승인이 없으면 후속 단계 작업을 중단한다. validation에서는 사람이 직접 review도 기록한다. 자동 단계의 범위 변경은 PRD 재승인 대상으로 돌린다.
- 재개 요청을 받으면 check로 사람이 실제로 기록한 승인/리뷰와 해시의 유효성을 다시 확인한다. 채팅이나 오래된 체크 결과는 승인이 아니다.

## 범위와 증거

- CLI: `node tools/design-harness/bin/design-harness <command> --root <repo> --project <id>`. check 종료 코드 1은 미통과, 2는 입력·파일·도구 오류다. currentStage·status·issues·canApprove를 함께 읽는다.
- 위임된 단계 폴더만 수정한다. 공통 기준·제품 코드·다른 단계 변경이 필요하면 이유와 영향 경로를 조정자에게 반환한다. --force는 자신이 관리하는 생성 파일의 의도한 재생성에만 사용한다.
- 캡처를 이미지 도구로 직접 연다. 경로·설명·캡처 생성 성공만으로 시각 검수를 대신하지 않는다. 관찰·해석·제안·실제 조작 검증을 구분한다.
- Figma 연결·실제 노드 조회·캡처 실패는 blocked/미검증이다. HTML·SVG·빈 JSON을 실제 Figma 결과나 기능 동작으로 표시하지 않는다.
- UI 아이콘은 Figma에서 추출하지 않고 Lucide에서 의미를 선택해 프로젝트 컴포넌트로 사용한다.
- control/stages.json 자동 영속화는 아직 없다. 수동 passed 기록으로 CLI를 대신하지 않는다. 재개 메모는 조정자가 control/flow.md에 둔다.

## 반환

`단계/상태(ready|needs_revision|blocked) → 수정 파일 → 입력 경로/버전/해시 → 실제 실행·직접 본 캡처 → 미해결/결정 필요 → 다음 담당에게 넘길 내용`을 반환한다. ready는 작업 준비 완료이며 사람 승인이 아니다.

비평가는 읽기 전용으로 결과를 반환하고 조정자가 단계 폴더의 critique.md에 원문을 보존한다. 검토 입력 경로/해시·직접 연 캡처·기준·발견·영향·수정 제안·미검증을 담는다. AI 비평은 사람 reviews.json/승인을 대체하지 않는다. 비평과 수정을 승인 전에 끝내고 check를 다시 실행한다. 승인된 단계에 새 보고서를 추가해도 승인이 무효화될 수 있다.
